Reglas que la BD garantiza

  • Borrado en cascada: user → project → plan → version → comment; plan → action.
  • Un nombre de proyecto por usuario.
  • Un solo número de versión por plan; versión actual = máximo.
  • Una sola acción pendiente por plan: UNIQUE(plan_id) WHERE consumed = false.
  • Un comentario anclado tiene bloque y fragmento; uno general no tiene ninguno.
  • Enums nativos (pgEnum) para state, view_access y type. Ids uuid. Timestamps timestamptz.
  • El HTML vive solo en version.html_content. Postgres es el único estado.

Reglas que viven fuera de la BD

  • Bloque = elemento con id. Lo decide el agente; regla de la skill, no del servidor.
  • Anidación máxima de bloques: 1 nivel. El visor ignora ids más profundos; el servidor no valida.
  • El HTML se guarda tal cual llegó. Estilos y script del visor se inyectan en el front al renderizar.
  • "Agente escuchando" es estado en memoria del servidor, no columna.
  • El agente recibe siempre texto: block_id, fragment y comentario. Nunca imágenes.
